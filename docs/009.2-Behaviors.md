# 09.2 Behaviors

## Explication et méthodes

Un Behavior, c'est un hook que la Collection appelle toute seule à des moments clés de la vie d'un document : avant et après un insert, avant et après un update. C'est fait pour tout ce qui doit arriver « tout seul » à chaque sauvegarde, sans que chaque controller ait à y penser (les timestamps, le hash d'un mot de passe...).

Un Behavior, c'est **deux fichiers liés par convention** :

- un **trait** dans `Model/Document/Traits/` (`FooTrait`) : il déclare les propriétés que le behavior gère. Elles sont typées comme le reste, pas de propriété dynamique planquée.
- une **classe** dans `Model/Behavior/` (`FooBehavior`, qui étend `MasterBehavior`) : elle implémente les hooks.

```php
class MasterBehavior {
    public function beforeInsert(object $data, mixed $entity = null): void {}
    public function afterInsert(object $data, mixed $entity = null): void {}
    public function beforeUpdate(object $data, mixed $entity = null): void {}
    public function afterUpdate(object $data, mixed $entity = null): void {}
    public function beforeCreateEntity(mixed $data, mixed $entity = null): void {}
    public function afterCreateEntity(mixed $data, mixed $entity = null): void {}
}
```

Tu surcharges juste les hooks dont tu as besoin, les autres ne font rien.

**C'est le document qui décide.** Pour activer un behavior, il suffit que le Document fasse `use FooTrait`. La Collection regarde les traits du document et retrouve la classe du behavior par convention de nom : `...\Model\Document\Traits\FooTrait` → `...\Model\Behavior\FooBehavior`, dans le même namespace racine. Ça marche donc aussi bien dans `SkankyDev\` que dans `App\`.

Tu peux empiler plusieurs traits sur un même document, ils se composent. Si deux behaviors déclarent une propriété du même nom, PHP lève une erreur fatale explicite : c'est voulu, ça évite un conflit silencieux.

## L'exemple livré : TimedTrait / TimedBehavior

Il gère `created_at` et `updated_at` tout seul :

```php
trait TimedTrait {
    public ?DateTime $created_at = null;
    public ?DateTime $updated_at = null;
}

class TimedBehavior extends MasterBehavior {
    public function beforeInsert(object $data, mixed $entity = null): void {
        $data->created_at = new DateTime;
        $data->updated_at = new DateTime;
    }
    public function beforeUpdate(object $data, mixed $entity = null): void {
        $data->updated_at = new DateTime;
    }
}
```

Pour l'activer, un document fait `use TimedTrait;`, point.

Parfois tu veux sauver sans déclencher les behaviors, par exemple pour une écriture de maintenance qui ne doit pas toucher à `updated_at`. Dans ce cas : `Collection::_saveSneaky($document)`, un alias de `save($document, false)`.

## En créer un nouveau : HashedPasswordBehavior

Un exemple réel du projet : hasher `password` automatiquement avant un insert ou un update, sans que `RegisterController` ou `PasswordController` aient à s'en occuper.

Le trait est vide, il sert juste à activer le behavior (`User` déclare déjà `password` lui-même) :

```php
namespace App\Model\Document\Traits;

trait HashedPasswordTrait {}
```

Le behavior :

```php
namespace App\Model\Behavior;

use SkankyDev\Model\Behavior\MasterBehavior;
use SkankyDev\Utilities\Hash;

class HashedPasswordBehavior extends MasterBehavior {

    public function beforeInsert(object $data, mixed $entity = null): void {
        $this->hashIfNeeded($data);
    }

    public function beforeUpdate(object $data, mixed $entity = null): void {
        $this->hashIfNeeded($data);
    }

    private function hashIfNeeded(object $data): void {
        if (empty($data->password)) {
            return;
        }
        // déjà un hash reconnu (update qui ne touche pas le mot de passe) → on ne re-hash pas
        if (password_get_info($data->password)['algo'] !== null) {
            return;
        }
        $data->password = Hash::make($data->password);
    }
}
```

Et sur le document :

```php
class User extends MasterDocument {
    use TimedTrait, HashedPasswordTrait;

    public string|null $password = null;
}
```

Et c'est tout : `RegisterController` fait juste `UserCollection::_save($user)` avec un mot de passe en clair, et il ressort hashé en base, sans code spécifique dans le controller.
