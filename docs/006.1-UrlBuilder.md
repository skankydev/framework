# 06.1 L'UrlBuilder

Écrire les URLs en dur dans les vues, c'est le meilleur moyen de tout casser le jour où tu changes une route. Du coup on a l'UrlBuilder : tu lui donnes un tableau `link` qui décrit où tu veux aller, et il te sort l'URL qui va bien. Pratique pour les liens dans les vues, les `redirect()`, ou une URL absolue dans un mail.

Tu l'appelles via `$this->url($link)` depuis une vue, ou via le helper global `url($link, $absolut = false)` partout ailleurs (controllers, mails, etc).

## Le tableau link

```php
[
    'name'       => '',   // nom de la route déclarée (voir plus bas)
    'namespace'  => '',   // le module, ex: 'App'
    'controller' => '',
    'action'     => '',
    'params'     => [],
    'get'        => [],
]
```

Aucune clé n'est obligatoire, et c'est fait exprès : tu ne remplis que ce qui change par rapport à la page courante. Ce que t'oublies (`namespace`, `controller`, `action`) est complété tout seul à partir de la route en cours (`completLink()`). Genre depuis une vue de `PostController`, `$this->url(['action' => 'edit', 'params' => [$id]])` suffit largement, pas besoin de tout réécrire.

`params` sert soit aux segments nommés d'une route déclarée (`:slug`, `:id`...), soit aux paramètres qui se rajoutent en bout d'URL par convention (`/controller/action/param1/param2`).

`get` te rajoute une query string (`?cle=valeur&...`), tout est urlencodé, tu t'en occupes pas.

## Par nom (le plus solide)

Si t'as déclaré ta route avec `->setName('...')` (voir [06 Le Routing](006-Le-Routing.md)), le plus simple c'est de construire l'URL directement par son nom :

```php
$this->url(['name' => 'password-reset', 'params' => [$userId, $token]])
```

L'avantage, c'est que tu redonnes pas controller/action/namespace à chaque fois, et surtout ça pète pas le jour où tu changes le schéma de la route (`/password/reset/:user/:token`) : seul le nom compte.

Si le nom que tu donnes correspond à aucune route déclarée, tu te prends une `RouteNotFoundException` direct. Pas de fallback silencieux qui te génère un lien cassé sans que tu t'en rendes compte, c'est le genre de bug qu'on découvre trois semaines plus tard sinon.

## Par convention / matching de route

Sans `name`, l'UrlBuilder cherche d'abord une route déclarée dont le controller/action/namespace correspond exactement à ton link. S'il en trouve une, il construit l'URL avec le schéma de cette route. Sinon il retombe sur la convention classique : `/namespace/controller/action/params...` (namespace et action sont omis quand c'est ceux par défaut de la config, histoire de pas polluer l'URL pour rien).

## Absolu

`$this->url($link, true)` (ou `url($link, true)`) te préfixe l'URL avec le schéma et l'host courant. Utile pour un lien dans un mail : une URL relative, ça veut rien dire une fois que c'est sorti du navigateur.
