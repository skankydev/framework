# 09.2 Behaviors

## Explanation and methods

A Behavior is a hook the Collection calls on its own at key moments in a document's life: before and after an insert, before and after an update. It's meant for everything that has to happen "on its own" on every save, without every controller having to think about it (timestamps, hashing a password...).

A Behavior is **two files linked by convention**:

- a **trait** in `Model/Document/Traits/` (`FooTrait`): it declares the properties the behavior manages. They're typed like the rest, no hidden dynamic property.
- a **class** in `Model/Behavior/` (`FooBehavior`, which extends `MasterBehavior`): it implements the hooks.

```php
class MasterBehavior {
    public function beforeInsert(object $data, mixed $entity = null): void {}
    public function afterInsert(object $data, mixed $entity = null): void {}
    public function beforeUpdate(object $data, mixed $entity = null): void {}
    public function afterUpdate(object $data, mixed $entity = null): void {}
    public function beforeCreateEntity(mixed $data, mixed $entity = null): void {}
    public function afterCreateEntity(mixed $data, mixed $entity = null): void {}
}
```

You just override the hooks you need, the others do nothing.

**The document decides.** To switch on a behavior, the Document just has to `use FooTrait`. The Collection looks at the document's traits and finds the behavior class by naming convention: `...\Model\Document\Traits\FooTrait` → `...\Model\Behavior\FooBehavior`, in the same root namespace. So it works just as well in `SkankyDev\` as in `App\`.

You can stack several traits on the same document, they compose. If two behaviors declare a property with the same name, PHP throws an explicit fatal error: that's on purpose, it avoids a silent conflict.

## The shipped example: TimedTrait / TimedBehavior

It handles `created_at` and `updated_at` on its own:

```php
trait TimedTrait {
    public ?DateTime $created_at = null;
    public ?DateTime $updated_at = null;
}

class TimedBehavior extends MasterBehavior {
    public function beforeInsert(object $data, mixed $entity = null): void {
        $data->created_at = new DateTime;
        $data->updated_at = new DateTime;
    }
    public function beforeUpdate(object $data, mixed $entity = null): void {
        $data->updated_at = new DateTime;
    }
}
```

To switch it on, a document does `use TimedTrait;`, period.

Sometimes you want to save without triggering the behaviors, for example for a maintenance write that mustn't touch `updated_at`. In that case: `Collection::_saveSneaky($document)`, an alias of `save($document, false)`.

## Creating a new one: HashedPasswordBehavior

A real example from the project: hashing `password` automatically before an insert or an update, without `RegisterController` or `PasswordController` having to deal with it.

The trait is empty, it's only there to switch on the behavior (`User` already declares `password` itself):

```php
namespace App\Model\Document\Traits;

trait HashedPasswordTrait {}
```

The behavior:

```php
namespace App\Model\Behavior;

use SkankyDev\Model\Behavior\MasterBehavior;
use SkankyDev\Utilities\Hash;

class HashedPasswordBehavior extends MasterBehavior {

    public function beforeInsert(object $data, mixed $entity = null): void {
        $this->hashIfNeeded($data);
    }

    public function beforeUpdate(object $data, mixed $entity = null): void {
        $this->hashIfNeeded($data);
    }

    private function hashIfNeeded(object $data): void {
        if (empty($data->password)) {
            return;
        }
        // already a recognized hash (update that doesn't touch the password) → don't re-hash
        if (password_get_info($data->password)['algo'] !== null) {
            return;
        }
        $data->password = Hash::make($data->password);
    }
}
```

And on the document:

```php
class User extends MasterDocument {
    use TimedTrait, HashedPasswordTrait;

    public string|null $password = null;
}
```

And that's it: `RegisterController` just does `UserCollection::_save($user)` with a plain-text password, and it comes out hashed in the database, with no specific code in the controller.
