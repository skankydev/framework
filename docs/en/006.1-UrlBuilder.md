# 06.1 The UrlBuilder

Hardcoding URLs in views is the best way to break everything the day you change a route. So we have the UrlBuilder: you give it a `link` array describing where you want to go, and it gives you back the right URL. Handy for links in views, `redirect()`s, or an absolute URL in a mail.

You call it through `$this->url($link)` from a view, or through the global helper `url($link, $absolut = false)` anywhere else (controllers, mails, etc).

## The link array

```php
[
    'name'       => '',   // name of the declared route (see below)
    'namespace'  => '',   // the module, e.g. 'App'
    'controller' => '',
    'action'     => '',
    'params'     => [],
    'get'        => [],
]
```

No key is mandatory, and that's on purpose: you only fill in what changes compared to the current page. Whatever you leave out (`namespace`, `controller`, `action`) is filled in automatically from the current route (`completLink()`). Like from a `PostController` view, `$this->url(['action' => 'edit', 'params' => [$id]])` is plenty, no need to rewrite everything.

`params` is used either for the named segments of a declared route (`:slug`, `:id`...), or for the parameters appended at the end of the URL by convention (`/controller/action/param1/param2`).

`get` adds a query string (`?key=value&...`), everything is urlencoded, you don't have to deal with it.

## By name (the most robust)

If you declared your route with `->setName('...')` (see [06 Routing](006-Routing.md)), the simplest thing is to build the URL directly from its name:

```php
$this->url(['name' => 'password-reset', 'params' => [$userId, $token]])
```

The upside is that you don't pass controller/action/namespace every time, and above all it doesn't break the day you change the route's pattern (`/password/reset/:user/:token`): only the name matters.

If the name you give doesn't match any declared route, you get a `RouteNotFoundException` straight away. No silent fallback generating a broken link without you noticing, that's the kind of bug you otherwise discover three weeks later.

## By convention / route matching

Without `name`, the UrlBuilder first looks for a declared route whose controller/action/namespace exactly matches your link. If it finds one, it builds the URL with that route's pattern. Otherwise it falls back on the classic convention: `/namespace/controller/action/params...` (namespace and action are left out when they're the config's defaults, so the URL isn't cluttered for nothing).

## Absolute

`$this->url($link, true)` (or `url($link, true)`) prefixes the URL with the current scheme and host. Useful for a link in a mail: a relative URL means nothing once it's out of the browser.
