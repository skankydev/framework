# 12.1 Fields

## How it works

Each field type (`text`, `select`, `checkbox`...) is a class that extends `FormField`. It does almost nothing by itself: its job is to point to a PHP template.

```php
class TextField extends FormField {
    protected string $type     = 'text';
    protected string $viewHtml = 'fields.default';
}
```

`$viewHtml` names the template, in dot notation like a regular view. For rendering, the template receives all of the field's properties.

To find the file, the framework first looks in the fields it publishes itself (`view.fields` config), otherwise it falls back on `view.folder`, the regular views folder. That lets you provide your own template for a field shipped with the framework, by putting it in your views folder, without touching the config.

`FormBuilder::add($name, $type, $options)` finds the class of `$type` through the `class.fields` config, a short alias to the full class (same idea as `class.rules` and `class.middlewares`):

```php
'class' => [
    'fields' => [
        'text'   => \SkankyDev\Form\Fields\TextField::class,
        'select' => \SkankyDev\Form\Fields\SelectField::class,
        // ...
    ],
],
```

An unknown type throws an exception right away, rather than quietly giving you a broken field.

### The common options of `add()`

```php
$this->add('title', 'text', [
    'label'           => 'Title',           // text of the <label>, otherwise $name as is
    'value'           => 'initial value',   // overwritten by old()/setData() if they have one
    'rules'           => 'required|max_length:120',
    'attributes'      => ['class' => 'form-input', 'placeholder' => '...'],
    'labelAttributes' => ['class' => 'form-label'],
    'id'              => 'CustomId',        // otherwise derived from the name
]);
```

`rules` feeds `FormBuilder::validate()` ([12.2](012.2-Validation.md)). A field without `rules` is simply never checked. The field also exposes `isRequired()` (true if `'required'` is one of the rules), handy to add a `required` CSS class on the label without repeating the information.

## The list of existing ones

`text`, `textarea`, `number`, `email`, `password`, `hidden`, `color`, `date`, `datetime`, `checkbox`, `radio`, `select`, `file`. They're all shipped with the framework and declared in `class.fields`.

Most of them have nothing more than the type and the template. Two exceptions to know about:

- **`select`** takes `options` (`value => label` pairs) and `empty` (adds an empty option at the top):
  ```php
  $this->add('status', 'select', ['options' => ['draft' => 'Draft', 'published' => 'Published'], 'empty' => true]);
  ```
- **`file`** renders an `<input type="file">`. As soon as a form contains a `file` field, the `FormBuilder` adds `enctype="multipart/form-data"` on the `<form>` on its own. When editing, if the value is a `StoredFile`, the current file is displayed above the field (thumbnail for an image). You get the uploaded file on the controller side with `$request->file('name')`, which gives you an `UploadedFile` ([05](005-The-Client-Request.md)), not through the form: files never go through `old()`, for obvious reasons.

## Adding one

You need three things: a class, an entry in `class.fields`, and a template.

```php
class RatingField extends FormField {
    protected string $type     = 'rating';
    protected string $viewHtml = 'fields.rating';

    protected int $max = 5;

    public function __construct(string $name, array $options = []) {
        parent::__construct($name, $options);
        $this->max = $options['max'] ?? 5;
    }
}
```

```php
'class' => [
    'fields' => [
        'rating' => \App\Form\Fields\RatingField::class,
    ],
],
```

Any public or protected property of the field (`$max` above, `$value`, `$errors`...) is automatically available in its template. No need to prepare a separate array of variables.

## Under the hood

`FormField::render()` resolves the template, then passes it all of the field's properties with `extract()`. That's what makes the properties directly usable by name in the template.
